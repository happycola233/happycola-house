先回顾一下近几个月内发现的一些离奇 bug，当然既然写在这就代表已经知道 why 了。

1. MSI 笔记本官方驱动，如果放在非 C 盘运行，会直接闪退。

   原因：CMD（命令提示符）默认工作目录位于 C 盘，而 MSI 的驱动启动 bat 中，在使用 `cd` 命令时未加 `/d` 参数，导致无法跨盘切换目录，从而导致无法找到同目录下的文件。

2. 之前帮别人装电脑，顺便安装微信，打开安装包后，弹出提示，“微信”正在运行请结束进程，但是点了之后安装程序就被关闭了。

   原因：安装包的名称被改为了 WeChat.exe，安装包认为进程中的 WeChat.exe 是已经安装完毕的微信主程序，殊不知这个 WeChat.exe 进程正是他自己。

3. 还是装驱动，路径超长，无法启动。

   原因：根据[微软官方文档](https://learn.microsoft.com/zh-cn/windows/win32/fileio/maximum-file-path-limitation?tabs=registry)：

   在 Windows API 中（以下段落中讨论了一些例外情况），路径的最大长度为 MAX_PATH，此项被定义为 260 个字符。系统按以下顺序构建本地路径：驱动器号、冒号、反斜杠、用反斜杠分隔的名称组件和终止 null 字符。例如，驱动器 D 上的最大路径为“`D:\某个 256 个字符的路径字符串<NUL>`”，其中“`<NUL>`”表示当前系统代码页的不可见终止 null 字符。（`<>` 字符在此用于醒目用途，不能作为有效路径字符串的一部分。）

嗯，然后今天又出现了一些离奇的 bug

起因是我今天用 “小米互传” 想传个代理配置 yaml 文件，结果发现传到手机上的文件竟然是 0 KB，我就匪夷所思啊，难道是我最近升级了 Beta 系统出 bug 了？因为这个 “小米互传” 其实是小米笔记本专属的，只不过我用了修改版才装到我的笔记本上，所以我也不好说他很稳定。后来我又传了照片等等，都没问题，我就十分不理解他这个 bug 的触发条件是什么。

解决：过了 1 个小时，我突然意识到是文件路径的问题，我要传输的 yaml 文件路径位于 `C:\Users\admin\Documents\✨我的文档`，没错路径中有一个“✨”，这是我为了好看加的 Emoji，经检验，这个 Emoji 就是导致传输异常的罪魁祸首。呵呵，我还想着怎么米冲高又有 bug 了，还好不是很严重的 bug，但是细节决定成败啊，怎么 Localsend 就没有这个问题呢？

第二个，这个就不算是 bug 了，本来想用快捷键 Ctrl + Shift + End，快速从光标处选到结尾的，怎么都用不了，我还怀疑是什么流氓软件和快捷键冲突了。最后发现，Num Lock 要关掉。这下我还真起劲了，以前就搞不懂 Num Lock 开着是能用小键盘数字还是不能用，直接上 GPT，好家伙，Num Lock 开着是能用数字啊，我还以为是锁起来是不能用......
